# แนวทางการทำงาน (Project Manifesto)

## หลักการทำงานร่วมกัน

### หลักการพื้นฐาน
1. **การวางแผนโดยนักพัฒนา**
   - นักพัฒนา (AI) เป็นผู้เสนอหัวข้อการพัฒนาถัดไปตามที่ถูกวางแผนมา แต่เป็นลำดับที่ต้องทำต่อ
   - Product Owner ให้คำแนะนำและกลั่นกรองความต้องการ
   - แต่ละฟีเจอร์ควรมีขนาดที่เหมาะสม สามารถพัฒนาเสร็จภายในหนึ่งวัน

2. **กระบวนการกลั่นกรองความต้องการ**
   - เริ่มต้นด้วยการพูดคุยก่อนเริ่มเขียนโค้ด
   - ปรับความต้องการให้สอดคล้องกับมาตรฐาน ADS design system
   - บันทึกความต้องการที่ผ่านการกลั่นกรองใน AI memory
   - แบ่งงานเป็นส่วนย่อยที่จัดการได้

3. **การทำเอกสารก่อนการพัฒนา**
   - อัปเดตเอกสารก่อนเริ่มพัฒนา
   - รักษาเอกสารให้ทันสมัยตามการเปลี่ยนแปลง
   - ใช้เอกสารเป็นแหล่งอ้างอิงหลัก

### ขั้นตอนการทำงานรายวัน
1. **เริ่มต้นเซสชัน**:
   - ทบทวนและอัปเดต sprint-progress.md
   - พูดคุยเกี่ยวกับฟีเจอร์/งานที่เสนอ
   - กลั่นกรองความต้องการ
   - บันทึกการตัดสินใจ

2. **ระหว่างการพัฒนา**:
   - ทำตามความต้องการที่บันทึกไว้
   - ติดตามความคืบหน้า
   - บันทึกการเปลี่ยนแปลงหรือสิ่งที่ค้นพบใหม่

3. **จบเซสชัน**:
   - อัปเดต sprint-progress.md ด้วยสิ่งที่สำเร็จ
   - บันทึกปัญหาหรือสิ่งที่ค้างอยู่
   - วางแผนสำหรับเซสชันถัดไป

### แนวทางการทำเอกสาร
1. **การอัปเดตความคืบหน้าของ Sprint**
   - อัปเดตเมื่อเริ่มและจบเซสชัน
   - ติดตามงานที่เสร็จและความต้องการใหม่
   - บันทึกปัญหาและอุปสรรค

2. **การเชื่อมโยงเอกสาร**
   - อ้างอิงเอกสารที่เกี่ยวข้อง
   - รักษาความสัมพันธ์ระหว่างฟีเจอร์
   - รักษาเส้นทางการนำทางให้ชัดเจน

3. **การบันทึกการตัดสินใจ**
   - บันทึกการตัดสินใจที่สำคัญทั้งหมด
   - รวมบริบทและเหตุผล
   - ติดตามผลกระทบต่อฟีเจอร์อื่น

4. **การอ้างอิงมาตรฐาน**
   - อ้างอิงมาตรฐาน ADS อย่างชัดเจน
   - บันทึกการเบี่ยงเบนจากมาตรฐาน
   - รักษาความสอดคล้องกับ design system

### มาตรฐานคุณภาพ
1. **คุณภาพโค้ด**
   - ทำตามข้อกำหนดที่วางไว้
   - รักษาความสอดคล้องกับโค้ดที่มีอยู่
   - คำนึงถึงผลกระทบต่อประสิทธิภาพ

2. **คุณภาพเอกสาร**
   - เขียนอย่างชัดเจนและกระชับ
   - อัปเดตสม่ำเสมอ
   - จัดรูปแบบและโครงสร้างอย่างเหมาะสม

3. **คุณภาพฟีเจอร์**
   - สอดคล้องกับ ADS design system
   - ตรงตามมาตรฐานการเข้าถึง
   - รองรับการแสดงผลแบบ responsive

### โปรโตคอลการสื่อสาร
1. **ระหว่างเซสชัน**
   - บันทึกการส่งมอบงานที่ชัดเจน
   - บันทึกข้อสันนิษฐาน
   - รายการคำถามหรือข้อกังวล

2. **ระหว่างการพูดคุยเรื่องความต้องการ**
   - การมีส่วนร่วมจากทั้งสองฝ่าย
   - บันทึกการตัดสินใจอย่างชัดเจน
   - ยืนยันความเข้าใจ

3. **ระหว่างการพัฒนา**
   - อัปเดตความคืบหน้าสม่ำเสมอ
   - แจ้งปัญหาแต่เนิ่นๆ
   - เอกสารทางเทคนิคที่ชัดเจน

### การปรับปรุงอย่างต่อเนื่อง
- ทบทวนแนวทางการทำงานนี้อย่างสม่ำเสมอ
- อัปเดตตามประสบการณ์ที่ได้เรียนรู้
- เพิ่มหลักการใหม่ตามความเหมาะสม
- ลบหรือปรับเปลี่ยนแนวปฏิบัติที่ไม่มีประสิทธิภาพ
